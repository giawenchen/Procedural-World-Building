# Project learning record

These instructions apply to work throughout this course repository.

- When implementing a new user idea or materially changing the app, also save real progress screenshots and a brief explanation. This is part of completing the change.
- Before changing visuals, capture the current app if possible. Capture the result afterward with matching camera, viewport, settings, and simulation step where appropriate. Explain differences; never invent a missing before image.
- Preserve the user's current simulation while documenting it. Prefer pause and original-preview controls over resetting or advancing their experiment.
- Use the existing running app/server when available; do not create a second sandbox unnecessarily.
- Save actual screenshots (PNG or JPEG, with the correct file extension) under `docs/tutorials/images/YYYY-MM-DD/`. Inspect them, verify the files exist, and use relative Markdown image links that work in Obsidian and GitHub. A screenshot shown only in chat is not a saved progress artifact.
- Maintain `docs/tutorials/YYYY-MM-DD - Progress Log.md`: user prompt or clearly marked paraphrase, what changed, why, labeled screenshots, actual checks, and one next experiment. Append to the day's log without overwriting earlier experiments.
- Write learning notes in English, in plain, brief language. Separate the user's stated observations from development checks and suggested reflections. Never invent first-person feelings, results, or completed experiments.
- Update the relevant tutorial and Visual Changelog for material changes, and update README/backlog when feature status changes. Mark ideas and unverified behavior honestly.
- Tutorials are the shared Obsidian files: the user's vault Tutorials folder links to `docs/tutorials`. Keep one canonical copy; open updated notes in Obsidian when available and verify images there.
- If capture or verification is blocked, document exactly what is missing instead of claiming completion.
- Run checks appropriate to the changes. Commit/push when the user authorizes it; documentation and screenshots are included in that commit.

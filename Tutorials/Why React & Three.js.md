# Why React & Three.js?

> **How I learned this:** I didn't read the docs first. I gave my AI assistant (Claude Code) the course repo link — [jomasan/Procedural-World-Building](https://github.com/jomasan/Procedural-World-Building) — and asked: *"look at this course and tell me why it uses Three.js and React."* The AI fetched the repo, read the README, and explained the architecture back to me. These notes are my digest of that conversation.

## What this course actually builds

A **browser-based procedural world generator**: terrain, water, weather, life, and towns, all generated by algorithms. The core loop the course teaches is:

```
parameter → procedure → picture
```

You drag a slider (parameter) → an algorithm runs (procedure) → the planet updates in real time (picture). Once you understand this loop, the tech choices explain themselves.

## Why Three.js — it draws the world

- The worlds we generate are **3D**: sphere terrain, voxels, atmospheres, erosion. The browser's native 3D API is **WebGL**, but raw WebGL is painfully verbose.
- **Three.js is the standard WebGL wrapper**: a few lines give you a scene, meshes, cameras, and lights.
- Later course topics — **LOD (level of detail), streaming, performance optimization** — are all standard practice in the Three.js ecosystem.
- Because everything runs in the browser, my homework can be **deployed as a website** (this is the "Hosted Website" item on the course checklist). Anyone with a link can play with my planet — no Unity/Unreal install needed.

## Why React — it controls the world

- The core interaction is **a panel full of sliders and parameters**: change "sea level" or "noise frequency" and the planet regenerates.
- That is exactly what React is good at: **UI state management**. Parameter changes automatically sync to both the interface and the data.
- With **TypeScript + React**, managing dozens of settings is far cleaner and less error-prone than hand-written vanilla JS forms.

## How they divide the work

The course README is explicit about this architecture:

| Layer | Owner | Job |
|-------|-------|-----|
| Algorithm layer | plain TS functions | procedural generation |
| Parameter layer | React state | sliders, settings |
| Render layer | Three.js | the 3D canvas |

React manages the UI panel; Three.js manages the 3D canvas. The two sides **communicate only through plain data (parameter objects)** — they never poke at each other's internal objects. Clean separation.

## The rest of the stack

- **Vite** — build tool / dev server (`npm run dev`)
- **npm / Node.js** — installs and runs everything → see [[How to Get Started with Node.js in Cursor & Claude]]
- **Firebase / Supabase** (later modules) — auth, database, hosting

So the course quietly teaches a **complete, shippable modern web stack**, not something that only runs in a classroom.

## Takeaway on learning with AI

Asking the AI *"why this stack?"* before writing any code gave me a mental model of the whole system in ~5 minutes. The key was giving it the **actual course repo** to read, instead of asking a generic "React vs X" question.
